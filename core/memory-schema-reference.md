# Memory Schema Reference

> **EMPIRA component**
> Component ID: `memory-schema-reference`
> Version: `1.3.0`
> Included in: `EMPIRA 0.1.0`

Цей документ описує **поточну структуру Memory** та версіонується незалежно від `Memory System Guide`.

Правила роботи з Memory визначає `Memory System Guide`.

## Типи об'єктів

- **Проєкт** — тривала діяльність або ініціатива з власним станом і розвитком.
- **Людина** — людина, про яку потрібен окремий довгостроковий контекст.
- **Річ** — значущий фізичний або цифровий об'єкт.
- **Знання** — сформоване розуміння, факт, концепція або стійкий контекст.
- **Рішення** — прийняте рішення, яке важливо пам'ятати окремо.
- **Подія** — значуща подія у певний момент або період.
- **Джерело** — документ, система, репозиторій, чат, база або інше важливе джерело інформації.
- **Організація** — компанія, установа, спільнота або інша організаційна сутність з власним довгостроковим контекстом.
- **Процес** — повторюваний або визначений порядок дій, який важливо пам'ятати окремо.
- **Завдання** — довгоживуча відкрита дія, рішення або очікування, яке має значення між чатами й сесіями та потребує окремого відстеження. Не використовуй цей тип для дрібних оперативних справ і не перетворюй Memory на таск-менеджер.

Використовуй лише наявні типи. Якщо жоден не підходить — дій за `Memory System Guide`.

## Межі об'єктів

Не створюй окремий об'єкт лише через появу нової названої сутності або концепту. Сама згадка, назва, зовнішня незалежність сутності або можливість у майбутньому накопичувати інформацію про неї не вимагають окремого об'єкта.

Створюй окремий об'єкт, коли сутність набуває власного довгострокового контексту, який уже не є лише частиною контексту іншого об'єкта.

Створюй окремий об'єкт також тоді, коли сутність потрібна як самостійна точка посилання для довгострокового контексту: коли важливо зберігати зв'язки саме з нею як із конкретною сутністю, а не лише згадувати її всередині іншого об'єкта.

Якщо вкладена сутність згодом стає окремим об'єктом, не видаляй важливий контекст її появи та ролі з початкового об'єкта. Деталі, що стосуються вже самої нової сутності, перенеси до її об'єкта. У початковому об'єкті збережи важливий контекст її ролі та додай `Related` на новий об'єкт.

**Рішення.** Не кожне прийняте рішення потребує окремого об'єкта `Рішення`. Якщо вибір лише визначає актуальний стан іншого об'єкта або пояснює окрему зміну в ньому, зберігай його в контексті цього об'єкта.

Створюй окреме `Рішення`, коли важливо довгостроково пам'ятати сам факт вибору — що було вирішено, чому, чи залишається рішення актуальним або чим воно було замінене. Окреме `Рішення` повинно мати самостійну цінність і не дублювати лише актуальний стан іншого об'єкта.

## Домени

Поточні домени: **Робота, Особисте, Родина, Навчання, AI, Розробка, Соціальне**.

Один об'єкт може мати кілька доменів. Якщо відповідного домену немає — не обирай слабко відповідний і не створюй новий самостійно; запропонуй необхідну зміну.

## Властивості

**Name** — коротка й однозначна назва об'єкта.

**Type** — один із наявних типів об'єктів.

**Domain** — одна або кілька наявних тематичних сфер.

**Status** — використовуй лише для типів, де статус має природний зміст:

- Проєкт → `Ідея`, `Активний`, `Призупинений`, `Завершений`, `Архівний`.
- Процес → `Активний`, `Періодичний`, `Призупинений`, `Завершений`, `Архівний`.
- Рішення → `Актуальне`, `Замінене`.
- Завдання → `Активний`, `Призупинений`, `Завершений`, `Архівний`.

Для інших типів залишай порожнім, якщо немає окремо погодженої потреби.

**Needs** — використовуй лише для `Завдання`; показує, що зараз потрібно, щоб відкритий хвіст зрушився: `До виконання`, `Потрібне моє рішення`, `Очікує зовнішнього`, `Завершено`. Для інших типів залишай порожнім. `Needs` не додає пріоритетів, дедлайнів, підзадач чи виконавців.

**Related** — об'єкти Memory зі змістовним зв'язком. Однакова тема сама по собі не є достатньою причиною для зв'язку.

**Date** — змістовна дата самого об'єкта, наприклад дата події або прийняття рішення. Якщо природної дати немає — залишай порожньою.

**Source URL** — пряме посилання на первинне або важливе зовнішнє джерело. Якщо джерело має власний довгостроковий контекст — використовуй окремий об'єкт `Джерело`.

**Summary** — 1–3 речення, достатні для розуміння суті та актуального стану об'єкта без читання повного вмісту.

**Створено** — автоматична дата й час створення запису.

**Оновлено** — автоматична дата й час останнього редагування.

AI не заповнює системні дати вручну. Вони не замінюють змістовну `Date`.

## Властивості та вміст

Властивості потрібні для пошуку, класифікації, зв'язків і швидкого розуміння об'єкта. Основний вміст сторінки містить деталі, контекст, причини, обмеження та іншу важливу інформацію.

**Не заповнюй властивості штучно. Якщо значення не має змісту для конкретного об'єкта — залиш його порожнім.**
